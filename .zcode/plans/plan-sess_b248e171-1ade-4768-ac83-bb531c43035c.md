## BACKEND

### 1. Session/cache integrity (real bugs, no money involved)
1. **`addReview` data corruption fix** (course.controller) — every new review currently overwrites `Course.purchased` with the review count, corrupting that counter. Stop writing it; recompute `ratings` with Prisma's `_avg` aggregate instead of loading every review into JS.
2. **Role changes take up to 7 days to apply** — `updateUserRoleService` updates the DB but never invalidates the Redis session cache that auth middleware reads. Add `redis.del(userId)`.
3. **Password change leaves old sessions alive** — `updatePassword` doesn't revoke refresh tokens; tokens issued before the change stay valid up to 7 days. Call `revokeAllRefreshTokens`.
4. **TTL hygiene** — shared `SESSION_CACHE_TTL_SECONDS` constant replacing the 6 hardcoded `604800`s (they desync with `REFRESH_TOKEN_EXPIRE` if the env changes); add EX to the one immortal session write in `updateProfilePicture`; `deleteUser` also revokes refresh tokens, not just the cache key.

### 2. Query shape (unbounded queries + N+1s)
1. **Public `getAllCourses`** — currently scans all courses + all sections + a JS-side join on every app launch, unbounded. Add `page`/`limit` params (default 12, max 50) with a total count.
2. **Admin listings** — users, INE verifications, notifications get limits/cursors (orders listing deferred with the money freeze).
3. `updateNotification` stops re-listing the entire notifications table after updating one row.
4. **Certificates list** — exclude the multi-KB `svgContent` from list responses.
5. **N+1 fixes**: credentials publish loop loads its context once per course completion instead of once per lesson (2N queries + N session restores today); analytics generator's 12 sequential COUNT round-trips → 2 `groupBy`s; `recordLessonProgress` merges its pre/post completed-lesson queries — this runs on every video progress ping.

### 3. Small integrity fixes
1. Thumbnail null-safety on course edit (`course.controller.ts` throws 500 for courses created without a thumbnail).
2. `syncCourseContent` removes `atprotoLessonRefs` keys for deleted lessons — today dangling refs silently skip credential publishing.

## FRONTEND (mobile)

### 4. React Query configuration — highest impact, smallest change
`QueryClient` is created with zero options → `staleTime: 0` → every tab switch refetches every list. Set defaults (staleTime 60s, retry 2, no window-focus refetch) and replace `CourseDetailScreen`'s unconditional focus-refetch with mutation-driven invalidation.

### 5. Lists + memoization
HomeScreen `ScrollView`+`.map()` → FlatList with header; CertificateList → FlatList; OptativeCarousel → horizontal FlatList with stable keys; `React.memo` on list rows (zero in the codebase today); `WelcomeLogin` module-scope `Dimensions.get("window")` → `useWindowDimensions`.

### 6. API/auth hygiene
CoursesScreen's raw-axios enrollment → the existing `useEnroll` mutation (correctly invalidates caches) plus `["courses"]` invalidation; a 401 rejection interceptor on the axios client that clears tokens and logs out via the auth context (today expired sessions just error per-screen); collapse the 8 duplicated `make*Hooks` instantiations into one shared factory.

### 7. First mobile test setup + CI
Vitest config in `packages/mobile` with tests for the pure utilities/theme helpers; CI gains a mobile test step (currently server-tests only).
